# 技术方案草案

日期：2026-11-12。产品行为以 `requirements-v0.1.md` 为准。以下是实施建议和待定项，尚无应用代码或依赖配置。

## 字幕材料与用户需求的区别

- 字幕是“供模型分析的材料”；学习目标是“用户希望从材料中得到什么”。二者应分别传递和校验。
- 首版由后端读取内置字幕，页面提交样例标识和学习目标。无需为了开发总结功能而先提供字幕上传接口。
- 接入视频后，由上传和转写流程提供字幕，再调用同一总结逻辑。视频入口和首版样例入口可以分别适配，不应把一个上传接口悄悄改成含义不同的需求接口。
- 学习目标从首版开始就是用户输入。接口路径和具体字段在 T02/T03 设计时确定，不承诺未来无需调整接口。

## 最小实现建议

```text
页面提交：样例标识 + 学习目标
    → 后端校验并读取固定字幕
    → 总结逻辑调用模型
    → 保存字幕快照、目标与结果
    → 返回已保存结果供页面展示

再次查看：结果编号 → 读取已保存记录 → 展示
```

- 首版采用一次提交等待结果的简单流程。页面的“正在生成”是等待反馈，不代表已经实现可恢复的后台任务。
- 先用一个清晰的模型调用边界支持固定响应和真实服务，便于开发与故障验证；两种运行方式必须能识别。
- 只有保存成功后才报告生成并保存成功。模型调用尽量放在本地数据库事务之外，避免等待外部服务形成长事务。
- 读取历史结果直接读持久化存储。保存时保留输入快照，避免后续修改内置样例后无法核对旧结果。
- 首版不自动重试模型调用，用户可以主动再次提交；不承诺跨标签页、网络重放或进程故障下的全局去重。
