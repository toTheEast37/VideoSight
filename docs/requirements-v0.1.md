## 用户与场景

目标用户是本地学习者。用户阅读系统内置的字幕样例，填写学习目标，获得与目标有关的学习总结，保存后可以重新查看。首版用于验证学习助手的最小闭环，并为后续视频分析准备基础。

## 已确认的范围

- 本地单人使用，无需登录或多用户隔离。
- 字幕由系统内置，用户可以修改学习目标；首版不提供字幕上传或粘贴任意文本的功能。
- 总结需要由真实模型生成；固定响应仅服务于开发和可控测试。
- 首版支持独立总结与历史查看；多轮追问和会话记忆放到下一阶段再确定具体需求。

## 输入、输出与流程

- **输入**：用户选择一个内置字幕样例，并填写非空学习目标。
- **输出**：针对目标的总结、核心知识点和可与字幕原文核对的依据；信息不足时明确说明。
- **流程**：查看样例 → 填写目标 → 提交生成 → 显示等待反馈 → 生成并保存成功 → 查看结果；之后可以重新打开已保存结果。
- **失败**：目标无效时提示修改；生成或保存失败时说明失败环节，保留目标并允许用户再次操作，不能提示已经保存成功。

## 可观察的验收标准

| 编号 | 场景与预期 |
| --- | --- |
| R01 | 进入页面能看到内置字幕；修改学习目标不会改变字幕原文。空白目标提交时有明确提示，不调用模型。 |
| R02 | 固定字幕配两个不同目标，真实模型输出分别回应对应目标；用人工核对的样例检查关键事实和原文依据，不要求每次措辞相同。 |
| R03 | 目标涉及字幕未提供的信息时，结果说明信息不足，不把外部猜测作为字幕中的事实。 |
| R04 | 成功提示出现后，刷新页面、重新打开结果以及重启应用后，均能读取同一条已保存结果，无需重新调用模型。 |
| R05 | 可控地模拟生成失败、超时或保存失败时，页面显示相应错误，保留目标、恢复提交能力，且不产生虚假的成功记录。 |
| R06 | 同一页面生成期间显示等待反馈并禁用提交；普通连续点击只发送一次生成请求。跨页面重复请求的处理不在本条承诺内。 |

## 暂缓功能

字幕文件上传、任意文本导入、视频上传、语音转写、画面文字识别、登录与多用户、后台任务与进度恢复、SSE、检索、多轮 Agent、分片上传、自动重试和公开部署均作为后续候选。多轮追问与会话记忆已明确放在下一阶段，当前不实现。

## 待确认的假设

- A01：历史查看已确认；具体展示暂建议为“时间、学习目标、打开详情”，先支持查看，暂缓编辑、删除和导出。“只读”限定历史记录的操作，不限制用户发起新的生成，也不表示数据库只能读取。
- A02：输出暂按“目标回应（针对目标的小结）、核心知识点（理解要点）、原文依据（对应字幕片段）”三个栏目展示，不承诺精确时间戳。这是内容栏目，不代表三个生成阶段或三次模型调用。
- A03：生成中刷新或退出后，暂不承诺新页面能继续跟踪原来的生成进度。刷新不一定会取消后端处理；如果结果最终保存成功，仍可从历史中查看。已经保存的结果继续按 R04 验收。

以上展示细节与刷新行为仍是建议，不能因历史查看已确认就视为全部确认。首项任务的样例、验证步骤与学习目标见 `tasks.md`。
