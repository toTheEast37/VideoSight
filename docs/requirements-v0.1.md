# 视频上传与文字解析 v0.1：需求与验收

更新日期：2026-11-19。用户已授权视频解析开发，并确认同时学习 MQ 与异步任务可靠性；11 月 19 日确认将独立 Outbox 的派发状态并入处理单元。本文维护产品行为；技术实现以 technical-notes.md 和代码为准，验证结果由 tasks.md 维护。

## 已确认的范围

- 本地单用户使用，无登录和用户隔离。
- 分阶段提供视频上传、独立文字解析和基于单个视频证据的问答。字幕总结、跨视频问答和多轮记忆继续暂缓。
- 使用分片上传；每个分片成功后记录成功序号。每轮开始前查询服务端进度，仅传缺片；本轮所有请求结束后再进行下一轮补传。
- 刷新页面后，重新选择同一份原文件，仍可继续原上传，复用成功分片。
- 后续可以找回已保存视频；上传过程与已完成资产需要分开定位。初始化重试返回同一上传会话，完成重试返回同一资产。
- 只有最终文件存储和数据库保存均成功后，才显示视频上传成功。分片齐全不等于最终保存完成。

## 视频上传的开发暂用边界

以下为本次落地所用的可调整开发值，不是用户指定的永久产品限制，也不是性能验证结论：

| 项目 | 当前暂用值 |
| --- | --- |
| 文件选择 | MP4、WebM、MOV；按声明的类型接收，不验证编码可播放性 |
| 单文件上限 | 2 GiB；未验证该大小文件的真实上传 |
| 每片大小 | 5 MiB，末片按实际剩余大小 |
| 补传 | 每次操作最多 3 轮，每轮前重新查进度；用尽后可手动继续 |
| 前端在途请求 | 最多 3 个；每个请求超时 60 秒，轮间等待 1 秒 |
| 续传期限 | 24 小时，成功分片后续期；到期明确提示重新开始 |
| 部署与列表 | 单后端实例；页面列出最近 100 条资产，按资产编号读取仍独立可用 |

## 视频上传用户流程

选择原视频 → 核对文件内容 → 创建或找回上传会话 → 分轮上传缺片 → 校验、合并与保存 → 显示已保存资产。

刷新后：重选原文件 → 找回原会话 → 查询成功序号 → 只补缺片。已完成后：从视频列表打开原资产，不需要原文件，也不需要再次上传。

失败时保留本地会话定位信息。查询进度失败不能按零进度重传；保存失败不能报成功；过期会话不悄悄创建新任务，用户必须明确选择重新开始。

## 视频上传验收（实现不等于全部实测通过）

| 编号 | 场景与预期 |
| --- | --- |
| U01 | 连续点击与初始化响应丢失后重试，仍使用同一请求键和上传会话；同键换文件应拒绝。 |
| U02 | 一轮中部分分片失败，其他分片仍可结束；下一轮查询后只补缺片，不重传服务端已确认的部分。 |
| U03 | 上传部分分片后刷新页面，重选原文件继续同一会话；不同内容不能混入原会话。 |
| U04 | 对象写入失败不记录成功序号；响应丢失后根据服务端进度继续，不仅依赖前端失败列表。 |
| U05 | 分片校验或合并失败、最终对象写入失败、数据库保存失败时，不显示已保存成功，允许合理重试。 |
| U06 | 重复完成返回同一资产；刷新和重启后能从数据库读回同一记录，读取不依赖临时 Redis 上传状态。 |
| U07 | 视频列表能打开或下载已保存对象；范围读取内容正确，对象缺失或存储不可用时不虚构成功读取。 |
| U08 | 会话过期时明确提示；临时数据清理不删除已完成视频，清理失败可再次处理。 |
| U09 | 上传服务未启用时页面显示真实配置状态，不允许发起假上传。 |

2026-11-16 已使用真实 MySQL、Redis、MinIO 和浏览器验证约 12.5 MiB、3 片 WebM 的上传、刷新重选续传、注入请求失败后的按轮补传、重复初始化与完成、下载及播放。应用重启后，全新浏览器仍能读取同一资产。失败注入、可控测试和真实服务的具体证据分别记录在 tasks.md；这不代表 2 GiB 性能或所有异常均已在真实环境实测。

## 本轮文字解析范围

以下为 2026-11-17 已确认的产品方向；具体服务和参数属于下方技术落地选择，不表示全部真实验收已完成。

- 主要处理中文课程、PPT 与代码录屏，提取语音文字和抽样画面中的文字。
- 从已保存视频手动点击解析，以 `assetId` 定位原视频；不要求重新上传，不携带学习目标，不自动生成总结。
- 解析在后台进行。任务受理后，页面可以关闭；再次打开同一视频时，从持久记录读取任务及已经保存的文字。
- 分别显示等待、处理中、完成、部分完成与失败；语音识别成功、数据库保存成功和页面读取成功分别判断。
- 成功片段保留；手动重试只重新处理失败或明确确认后待重试的部分，不因 OCR 失败重新调用已完成 ASR。
- 当云端语音或画面识别可能已被受理但无法确认结果时，不自动再次提交。页面说明可能重复计费，由用户确认后重试。
- 解析配置更新后，页面可继续查看旧结果。用户可选择用当前配置重新解析原视频并保存新任务。
- 识别结果用于后续学习材料准备。语音时间表示音频片段范围，画面时间表示抽样截图时刻；不承诺句子级对齐、完整字幕、说话人区分、动作或图表理解，也不保证还原代码符号和缩进。
- 本轮继续采用本地单人、单后端实例；引入 RocketMQ、持久任务与恢复检查，但不承诺跨实例协调或外部识别恰好调用一次。

## 文字解析的开发暂用边界

以下为可调整的开发值，不是用户指定的永久限制，也不代表上限性能已验证。上传允许保存的文件可能超过当前解析范围。

| 项目 | 当前暂用值 |
| --- | --- |
| 原视频 | 已保存资产，解析上限 256 MiB、30 分钟；检查实际视频轨道与时长；整体起始时间绝对值超过 1 ms 时明确拒绝，音轨自身延迟仍支持 |
| 音频 | 提取为 16 kHz、单声道 PCM WAV，按约 60 秒分片 |
| ASR | 阿里云百炼 `qwen-audio-3.1-asr-flash`，每片通过 Data URI 同步调用非流式接口 |
| 画面 | 每 5 秒抽样一次，最多 360 帧；不以采样间隔推断文字出现和消失时间 |
| OCR | 默认本地 Tesseract，可显式切换到百炼 `qwen3.5-ocr`；两者均保存原始转录和采样时间 |
| 并发与等待 | 一个后台消费线程逐项处理；受理返回任务编号，页面轮询读取状态 |
| 自动重试 | 可确认的暂时失败最多尝试 3 次，计费结果不确定的云端识别等待用户确认 |

## 文字解析用户流程

打开已保存视频 → 读取原任务 → 尚未解析且服务可用时手动开始 → 任务持久受理 → 后台预处理、分片识别并逐项保存 → 查看语音和画面文字。

刷新或重启后：打开同一视频 → 从服务端找回原任务与结果，不依赖浏览器内存恢复进度。提交响应丢失时，先查询受理结果；无法确认时暂停，不换一个请求键盲目重建任务。

部分失败后：查看成功结果与失败原因 → 在服务可用时重试未完成部分。若存在可能已计费的未知请求，先阅读说明，再明确接受可能重复计费并重试。

## 文字解析验收（逐项证据见 tasks.md）

| 编号 | 场景与预期 |
| --- | --- |
| P01 | 连续点击、提交响应丢失、刷新后再次打开，仍查询或复用原任务；同请求键绑定其他资产应拒绝；不同请求键提交同资产与同解析配置也不新增重复任务。 |
| P02 | 任务、处理单元及其待派发状态同事务保存；数据库失败不得返回已受理，MQ 暂不可用时保留单元的待派发状态，恢复后继续投递，不将排队显示为识别成功。 |
| P03 | Broker 已收消息但本地发送回执保存失败、重复消费、过期执行者回写时，完成片段不重复识别；旧执行结果不能覆盖新执行结果。 |
| P04 | 每个音频片和抽样画面保存独立结果；部分失败显示部分完成，重试只处理失败项，保留成功文字与原调用结果。 |
| P05 | ASR 超时、异常响应、处理中断或外部成功而数据库保存失败时，不误报保存成功，不自动再次提交可能计费的请求；明确确认后才重试。 |
| P06 | 页面刷新、应用重启后可从数据库读取同任务与结果；排队消息遗失可补发，过期执行按阶段恢复；不能仅用内存替身证明真实重启读取。 |
| P07 | 无音轨明确跳过 ASR，不调用供应商；正常识别为空文本或截图无文字属于已保存的空结果，不能当作服务失败或编造文字。 |
| P08 | 超时长、超大小、无视频轨道、无法解码或媒体输入损坏时，说明原因，保留原资产；未通过检查不得继续付费识别。 |
| P09 | 解析未启用、配置缺失或可执行工具不存在时，显示真实不可用原因，不进行假解析；语言数据或工具运行失败应成为可见失败。解析开关关闭时，仍允许读取已有历史。 |
| P10 | 页面区分音频片段范围与截图采样时刻，不宣称句级精确定位；识别文字按纯文本显示，不能执行其中的 HTML。 |

2026-11-17 已使用本机生成的约 8.19 秒普通话与课程画面视频，完成真实 RocketMQ、MySQL、MinIO、百炼 ASR、本地 OCR 和浏览器完整链路；刷新及应用重启后可读取同一任务。另以无音轨视频验证 Broker 停机时持久排队、恢复后继续完成且跳过 ASR。并发、外部结果不确定和数据库失败等窗口另有可控自动化证据；不能将短样例成功扩大为课程识别质量、上限性能或全部真实故障验收。逐项范围见 tasks.md。

## 单视频单轮问答

- 用户从资料库选中一条视频并输入问题。页面提交资产编号和问题，后端使用该视频已保存的 ASR/OCR 原文。
- OCR 的检索副本在向量化前做格式清洗，供向量检索、关键词匹配和重排。页面和回答引用继续使用已保存的识别原文及采样时间。
- 每项回答展示至少一处原文引文及来源。ASR 显示音频片段起止时间，OCR 显示采样时刻。点击引文时间跳到该视频对应位置。
- 只有部分内容能得到支持时，展示有依据的部分并提示证据不足。证据无法回答问题时，明确显示证据不足。未解析、正在解析、解析失败和问答服务失败有各自提示。
- 同一页面请求处理中只发一次提交。切换视频后，旧请求的回答不能出现在新视频下。问答使用已保存的文字，不重新识别视频。
- 使用现有 MySQL 保存片段向量，在 Java 中计算余弦并加权排序。
- 同一次提问由 Planner 识别并拆出最多三个子问题，Executor 分别按加权召回生成草稿，Critic 逐项审查原文能否支持结论，并保留可核对的引用。询问具体字段名时，只有资料位置或章节线索仍属于缺证据。
- 只对首轮仍缺证据的子问题补查一次。补查使用定向加权召回和 Rerank，二次核对后逐项显示回答或证据不足。补查服务失败时明确显示该项未能完成补证，已核对的结论仍可查看。
