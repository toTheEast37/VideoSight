### 发现问题与修复

- `UploadService.initialize`：请求缺少 contentType 时，直接调用不可变 Set.contains(null) 会抛空指针并返回 500；已增加空值校验，统一返回 400。
- `UploadService.cleanupCompleted`：只记录清理失败日志会导致已完成会话永远不再进入过期清理；已增加与资产同事务提交的 cleanup_pending，并由调度及重复完成请求继续清理，完成后清除标志。仓储验证标志可跨实例重读，资产不因清理失败丢失。
- MinIO 9.0.4 的元数据 API 返回集合，且 Maven 需要显式 JVM HTTP 客户端依赖；已对齐 API、okhttp-jvm 和 Kotlin 依赖，并通过实际 SDK 替身读写验证。首轮测试另发现不合法的 Mockito 受检异常模拟，已修正后全部通过。
- Windows 预览进程占用 JAR 时重打包失败；停止本次预览进程后重打包成功。最新前端禁用状态修复已重新打入产物，避免检查旧资源。
- 真实 Redis 3.2.100 不支持多字段 HSET，初始化 Lua 首次执行失败；已改为同一 Lua 内逐字段 HSET，新增显式开启的真实集成测试，修复后通过。仅连接成功或模拟返回不能覆盖这一版本兼容问题。
- 本轮沙箱内默认 Java 检查停在 Mockito 初始化，已中止该次执行；在沙箱外重跑完整 verify 成功，随后独立运行真实 Redis 检查。未将中止执行计作通过。

### 人工可核对的固定样例

S01 是为学习编写的短字幕，后续实现应保留其固定内容，以便复现比较：

> 浏览器发送 HTTP 请求到服务器。Controller 接收参数并进行基础校验。Service 处理业务流程，需要保存的数据交给持久化层写入数据库。数据库保存成功，不代表浏览器一定收到响应；网络中断可能让客户端不知道最终结果。

- G01：按顺序解释一次请求如何得到并保存结果。
- G02：只关注失败时用户可能遇到什么问题。
- G03：说明字幕中提到的 Kafka 分区策略。

预期：G01 能说明主要调用顺序；G02 能说明“数据可能已保存但客户端未收到响应”；G03 明确指出字幕没有提供相应信息。总结的原文依据应能在 S01 中找到。

| C06 保存失败 | 在测试中让持久化操作失败。 | 页面说明未保存成功，保留目标、恢复提交能力，不新增成功记录或进入不存在的成功详情；不强制本轮实现“仅重试保存”。 | R05 |
| C07 连续点击 | 在同一页面连续点击生成，观察按钮和浏览器请求。 | 生成期间有反馈且提交按钮禁用，只发出一次生成请求。该结果不代表服务端具备全局幂等。 | R06 |

真实模型重点验证 C02—C04；可控替身验证异常路径。优先为持久化、失败后不报成功和外部调用边界保留有意义的自动化测试；同时进行实际页面操作。开发时再补充实际命令，当前表格是验证计划，不是通过记录。

### 完成后应能解释的知识点

1. **调用链**：页面提交后，Controller、Service、模型调用和持久化分别接收什么、返回什么。
2. **两类输入**：字幕是分析材料，学习目标表达用户需求；未来由视频转写提供字幕，总结逻辑仍可复用。
3. **持久化**：内存与持久保存有什么区别，结果编号如何用于重新读取，为什么保存输入快照。
4. **失败边界**：模型生成成功为何不等于保存成功；本地事务无法撤回已经发生的外部模型调用。
5. **验证边界**：固定响应能证明什么，真实模型验收为何需要人工核对，为什么不能断言每次措辞一致。
6. **请求边界**：按钮禁用只能覆盖什么场景，客户端未收到成功响应为何不一定表示服务端没有保存。
